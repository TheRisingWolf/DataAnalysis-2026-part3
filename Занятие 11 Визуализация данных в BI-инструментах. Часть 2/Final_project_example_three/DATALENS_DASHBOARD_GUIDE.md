# Подготовка дашборда в Yandex DataLens

## 1. Что загружать

Для основной вкладки используйте `data/datalens/datalens_sales_mart.csv`.

Дополнительные витрины:

- `datalens_monthly_sales.csv` — месяц = одна строка;
- `datalens_product_abc_xyz.csv` — один товар = одна строка;
- `datalens_customer_rfm.csv` — один клиент = одна строка;
- `datalens_category_channel.csv` — категория × канал = одна строка;
- `datalens_hypothesis_summary.csv` — одна статистическая проверка = одна строка;
- `datalens_kpi.csv` — одна строка с контрольными KPI полной очищенной выборки.

## 2. Рекомендуемая архитектура

### Вкладка 1. Обзор продаж

KPI:

- чистая выручка;
- валовая прибыль;
- маржинальность;
- количество заказов;
- средний чек;
- проданные единицы;
- доля возвратов.

Чарты:

- динамика выручки и прибыли по месяцам;
- выручка по категориям;
- выручка и прибыль по каналам;
- выручка по городам;
- Top-10 брендов/товаров;
- возвраты по категориям.

Селекторы: период, город, канал, категория, бренд, акция.

### Вкладка 2. Товарный портфель

Источник: `datalens_product_abc_xyz.csv`.

- таблица товара: выручка, прибыль, ABC, XYZ, комбинированный класс;
- матрица/тепловая таблица ABC × XYZ;
- Top товаров класса AX/AY;
- товары CZ как кандидаты на дополнительную проверку ассортимента.

### Вкладка 3. Клиенты

Источник: `datalens_customer_rfm.csv`.

- количество клиентов по RFM-сегментам;
- выручка по сегментам;
- средний Recency/Frequency/Monetary;
- таблица Top клиентов по Monetary.

### Вкладка 4. Проверка гипотез

Источник: `datalens_hypothesis_summary.csv`.

Показывайте вопрос, метод, статистику, p-value и интерпретацию. Не используйте p-value как доказательство причинности.

## 3. Важное ограничение интерактивности

ABC-XYZ, RFM и статистические тесты рассчитаны в notebook на фиксированной очищенной выборке. Если пользователь меняет селекторы на основной вкладке, эти предварительно рассчитанные результаты **не пересчитываются автоматически**. Для динамического пересчёта требуется отдельный расчётный слой/ETL или другая архитектура.

Если чарты построены на разных датасетах, не предполагайте автоматическую синхронизацию селекторов. В DataLens связи между виджетами разных датасетов настраиваются осознанно через совместимые поля/алиасы.

## 4. Рекомендуемые типы полей

- `sale_date`, `month_start` — Дата;
- `quantity`, `returned` — Число;
- денежные поля — Число с денежным форматом;
- `discount_pct`, `margin_pct`, доли — Число с процентным форматом;
- `city`, `sales_channel`, `category`, `brand`, `promo_campaign` — Измерения.

## 5. Формулы, которые можно оставить в DataLens

Если используется `datalens_sales_mart.csv`, основные денежные показатели уже рассчитаны в notebook. В DataLens удобно создавать повторно используемые показатели уровня датасета, например:

```text
SUM([net_revenue_rub])
SUM([gross_profit_rub])
COUNTD([order_id])
SUM([quantity])
AVG([returned])
```

Средний чек корректнее считать как отношение выручки к числу уникальных заказов на одном фильтрованном срезе:

```text
SUM([net_revenue_rub]) / COUNTD([order_id])
```

## 6. Проверка результата

Перед публикацией убедитесь, что:

- KPI без фильтров совпадают с `datalens_kpi.csv`;
- селекторы основной вкладки действительно меняют связанные чарты;
- единицы измерения и проценты оформлены явно;
- один и тот же KPI не вычисляется разными формулами в разных чартах;
- предрассчитанные ABC-XYZ/RFM/гипотезы не выдаются за динамически пересчитываемые результаты.
