# Кластеризация и классификация данных: практическая инструкция

## Цель

Научиться применять кластеризацию и классификацию как инструменты аналитика данных: находить группы похожих объектов, описывать их, прогнозировать известный класс и проверять качество результата.

## Исходная ситуация

Вы работаете аналитиком службы поддержки. Есть история обращений клиентов. Руководителю нужно понять, какие типы обращений существуют в данных и можно ли заранее определить обращения с повышенным риском нарушения SLA.

## Результат работы

После выполнения у вас должны быть:

- обращения с присвоенными кластерами;
- таблица профилей кластеров;
- сравнение качества baseline, Logistic Regression и Decision Tree;
- таблица прогнозов для тестовой выборки;
- краткие ответы на аналитические вопросы внутри notebook.

## Порядок работы

1. Откройте `notebooks/student_practice.ipynb`.
2. Выполните проверку окружения и найдите CSV.
3. Загрузите данные и проверьте структуру, пропуски и дубликаты.
4. Постройте исходный scatter plot двух признаков.
5. Выполните первую кластеризацию на двух признаках.
6. Масштабируйте расширенный набор признаков.
7. Сравните варианты `k = 2...6`.
8. Постройте итоговую модель K-Means для `k = 3`.
9. Сформируйте профиль кластеров через `groupby`.
10. Перейдите к задаче классификации `sla_breached`.
11. Исключите признаки, которые недоступны в момент создания обращения.
12. Разделите данные на train и test.
13. Рассчитайте baseline.
14. Обучите Logistic Regression и Decision Tree.
15. Сравните accuracy, precision, recall и F1.
16. Разберите confusion matrix и сформулируйте аналитический вывод.

## Самопроверка

Перед завершением убедитесь:

- notebook запускается сверху вниз;
- исходный датасет содержит 2500 строк;
- отсутствуют пропуски и дубликаты идентификаторов;
- перед K-Means выполнено масштабирование;
- сравниваются несколько значений `k`;
- кластеры интерпретируются через исходные признаки;
- при классификации нет `resolution_minutes` и других признаков будущего результата;
- preprocessing обучается внутри pipeline только на train;
- есть baseline;
- качество модели оценивается не только по accuracy;
- итоговые CSV и графики сохранены в `outputs/`.
